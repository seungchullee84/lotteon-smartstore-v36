# 상품등록기

## 네이버 연결과 검색키워드 자동 작성

화면 상단 `설정` 안의 `네이버 API 연결 설정`은 상품 수집 전에도 사용할 수 있습니다. 네이버 클라우드 콘솔 → NAVER API HUB → Application → 인증 정보에서 발급한 Client ID·Client Secret을 입력하세요. 해당 Application에 검색어 트렌드 권한이 필요합니다. 기존 네이버 개발자센터의 키는 API HUB에서 사용할 수 없습니다. [공식 이관 안내](https://guide.ncloud-docs.com/docs/apihub-migration)를 참고하세요. 저장 전에 실제 조회로 인증·권한을 확인하며 실패한 키는 기존 설정을 덮어쓰지 않습니다. `네이버 연결 확인`으로 다시 확인할 수 있습니다.

상품 수집 후 관련 품목·성별·실제 특성으로 후보를 만들고 최근 28일의 데이터랩 검색 상대지수를 비교해 검색키워드를 자동 작성합니다. 브랜드를 먼저 넣고 관심도가 높은 후보부터 단어 단위로 추가하며 쉼표 포함 40자 이내로 맞춥니다. 관련 후보가 부족하면 억지로 40자를 채우지 않습니다. 여러 요청의 상대지수는 공통 기준 키워드로 환산해 비교하며 월간 절대 검색량·매출 순위를 뜻하지 않습니다. 기준 검색 자료가 없거나 API 조회가 실패하면 기존 입력을 유지합니다. 조회 중 직접 수정한 입력도 덮어쓰지 않습니다.

검색키워드 40자 변경의 전후 결과, 모의 검증과 Windows 적용 방법은 [KEYWORDS-40.md](KEYWORDS-40.md)를 확인하세요.

롯데ON·스마트스토어 상품등록 도우미입니다. 소스 파일 변경을 감지해 버전과 한국 시간 기준 최종 수정일(요일 포함)을 자동 갱신합니다. 실행 중에는 약 2초 간격으로 확인하며, 종료 중 수정한 내용은 다음 실행 시 반영합니다. 상품 데이터·로그·브라우저 프로필은 버전 계산에서 제외합니다.

## 실행

Windows, Node.js 20.19 이상 및 구글 크롬(Google Chrome)이 필요합니다.

```sh
npm install
npm run setup
npm start
```

Windows에서는 `start.cmd`로도 실행할 수 있습니다. 판매자 계정은 실행 후 열리는 전용 크롬 창에서 직접 로그인하세요. 실제 상품 등록 전 수집 정보와 입력 내용을 확인하세요.

## 배경 늘리기·합성

`배경 늘리기·합성` 버튼을 눌러 대표이미지·추가이미지 1·추가이미지 2 중 한 장을 선택하고 원본을 확인한 뒤, 등록기를 함께 열어 둔 현재 채팅에 `합성해줘`라고 보내세요. 채팅에서 내장 이미지 생성 도구로 합성하고 대표이미지에 적용합니다. 버튼은 안내를 표시하며 채팅 메시지를 자동 전송하지 않습니다. API 키 입력은 필요하지 않습니다.

완성된 결과는 현재 수집한 상품 폴더에 1500×1500 JPEG로 저장되며 대표이미지 미리보기·저장·업로드에 자동 적용됩니다. 실패하거나 중단하면 기존 대표이미지를 유지합니다. 상품을 외부 판매처에 저장하거나 등록하는 동작은 별도입니다.

## 공개 범위

프로그램 소스, 화면, 테스트, 분류표 및 OCR 언어 파일을 포함합니다.
로그인 브라우저 프로필, 세션 토큰, 비밀번호 설정, 상품별 작업 기록, 로그 및 개인 Codex 채팅 연결은 포함하지 않습니다.

기존 비공개 저장소와 실행 중인 로컬 앱은 그대로 유지됩니다.

## GitHub 자동 반영

프로그램이 실행 중이면 저장된 소스 파일의 변경을 확인하고, 수정이 1초 동안 멈춘 뒤 약 2~4초 후 자동 커밋·업로드를 시작해 연결된 GitHub main 브랜치에 반영합니다. 업로드 완료까지는 네트워크 상태에 따라 시간이 더 걸릴 수 있습니다. 화면 상단에서 반영 상태를 확인할 수 있습니다. 종료 중 수정한 파일은 다음 실행 시 반영합니다. Git 설치와 해당 저장소에 대한 Git 로그인 권한이 필요합니다. 이 프로젝트는 main에서 작업합니다.

로그인 프로필, 토큰, 환경변수 파일, 상품 사진·작업 기록과 data 폴더는 자동 업로드하지 않습니다. 인증 문자열로 보이는 내용이 발견되면 업로드를 중단합니다. 네트워크 오류는 다시 시도하며, 원격 변경과 충돌하면 덮어쓰지 않고 확인 메시지를 표시합니다.

합성 선택은 현재 상품 폴더의 `background-selection.json`에 저장됩니다. 채팅에서 합성할 때 이 파일의 key(main/extra1/extra2)를 확인하여 해당 원본(key.jpg)을 사용합니다. 완성본은 key-composite-24자리소문자hex.jpg로 저장하며, 대표이미지는 background-image.json, 추가이미지는 background-image-extra1.json 또는 background-image-extra2.json에 {"file":"완성 파일명"}을 기록하면 해당 미리보기·저장·업로드에 반영됩니다.

## 합성 결과 적용 원칙

사용자가 대표이미지·추가이미지 1·추가이미지 2 중 어느 원본을 선택하더라도, 완성된 합성본은 항상 현재 상품의 대표이미지에 적용합니다. background-selection.json의 key는 합성에 사용할 원본만 정합니다. 결과는 main-composite-24자리소문자hex.jpg로 저장하고 background-image.json에 {"file":"완성 파일명"}을 기록합니다. 대표이미지 미리보기와 저장·업로드 파일까지 반영 여부를 확인합니다.

추가이미지 오른쪽 위의 × 버튼을 누르면 해당 상품의 미리보기와 추가이미지 업로드 대상에서 제외합니다. 원본 파일은 보존하고 excluded-extra-images.json에 제외 상태를 저장하므로 서버를 다시 실행해도 유지됩니다. 대표이미지는 변경하지 않습니다.

## 색상칩 배치 규칙

- 지오다노 공식 상품 페이지의 실제 색상칩 이미지를 사용합니다. 색상명 텍스트는 넣지 않습니다.
- 대표이미지 오른쪽 하단에 세로로 배치합니다. 1500×1500 기준 칩은 72×72px, 얇은 테두리를 포함해 약 74px, 칩 사이 간격은 약 14px, 오른쪽·하단 여백은 약 10px입니다.
- 오른쪽 하단이 인물·의상·상품과 겹치거나 여백이 부족하면 오른쪽 중단으로 옮깁니다.
- 오른쪽 중단도 여백이 부족하면 색상칩을 생략합니다. 칩을 넣기 위해 배경을 강제로 늘리거나 인물·의상을 자르거나 축소하지 않습니다.
- 색상칩 배치는 공식 칩을 그대로 합치는 방식으로 처리합니다. 배경 합성이 별도로 필요하지 않으면 AI로 사진을 다시 생성하지 않습니다.
- 최종 결과는 1500×1500 JPEG로 저장하고 현재 상품의 대표이미지 미리보기·저장·업로드에 적용됐는지 확인합니다. 원본 파일은 보존합니다.

상품 수집 완료 시 공식몰 색상칩을 자동으로 내려받아 대표이미지에 배치합니다. 대표이미지 표시·저장·업로드 모두 같은 색상칩 포함 파일을 사용합니다. 하단과 중단의 오른쪽 영역이 밝고 단순한 배경인지 보수적으로 검사하며, 무늬·물체·어두운 배경 등 여백 여부가 불확실하면 생략합니다. 칩 다운로드 실패는 상품 수집을 막지 않습니다. 이후 대표이미지를 합성본으로 바꾸면 새 사진의 여백을 다시 검사해 배치합니다.

## 스마트스토어 상품명 제안

스마트스토어 전용 상품명 칸에서 네이버 데이터랩 검색 상대지수를 조회해 표현을 제안합니다. 롯데ON 상품명·키워드는 유지합니다. 처음 한 번 네이버 API 키 설정이 필요합니다. [사용 방법과 검증 범위](SMARTSTORE-TITLE.md)를 확인하세요.

## 다른 PC용 Windows 실행판

`build-portable.mjs`로 Windows 10/11 x64용 실행판을 만듭니다. Node.js와 Playwright 수집용 Chromium을 포함하며, 설치된 Chrome이 없으면 포함된 Chromium으로 판매처 로그인 창을 실행합니다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "D:/CodexStorage/Browsers"
node build-portable.mjs "C:/배포/상품등록기-Windows"
```

출력 폴더 전체를 ZIP으로 전달하고 다른 PC에서는 압축을 해제한 뒤 `상품등록기.exe`를 실행합니다. EXE만 따로 복사하지 않습니다. 첫 실행 때 네이버 API 키를 입력하고 판매자 계정에 직접 로그인합니다. 키·토큰·로그인·상품 작업 자료는 배포에 포함하지 않습니다. 배포판은 GitHub 자동 업로드를 실행하지 않으며 원본 프로젝트의 자동 반영은 유지됩니다.

### 아이템스카우트 카테고리 조사 자료

`data/category-itemscout-verified.json`은 사용자가 제공한 `itemscout-verified-categories.csv`의 320개 키워드, 411행을 원문 필드 그대로 보존합니다. 월간 검색수, 카테고리 비중, 출처 URL, 조사일 및 미확인 사항을 포함합니다.

네이버 검색키워드·스마트스토어 상품명 최적화 시 후보를 이 자료와 대조합니다. 상품 성별·종류의 전체 경로가 같고 단일 경로 비중이 100%인 키워드만 `verified`로 표시합니다. 다른 경로 또는 비중이 분산된 조사 키워드는 API 비교와 순위에서 제외합니다. 자료에 없는 후보는 `unverified`로 유지하고, 상품 종류·성별을 판단할 수 없는 조사 후보는 검토 대상으로 제외합니다. 미조사 후보까지 검증되었다거나 전체 의류 매칭이 100% 완료되었다는 의미는 아닙니다.

조사 자료는 검색키워드 검토에 사용하며 롯데ON 분류 코드나 스마트스토어 복사 양식의 선택 카테고리를 변경하지 않습니다. 월간 검색수는 자료의 원문 수치이며, 네이버 데이터랩의 검색 상대지수와 합산하거나 서로 대체하지 않습니다. API 응답의 `categoryAudit`에서 적용·제외 근거를 확인할 수 있습니다.

## 다른 컴퓨터에서 성인 소구점 분석 이어가기

GitHub main 최신 코드를 Git으로 받아 의존성과 수집 브라우저를 설치하고 등록기를 실행하면, 공유된 공식 조사자료를 로컬에 복원한 뒤 남은 성인 상품 분석을 자동으로 시작합니다. 완료된 이미지 OCR은 원본 파일이 그 컴퓨터에 없어도 재사용하고 미완료 상품의 공식 원본은 다시 받습니다. 등록기에 적용할 때에는 현재 품번·공식 상품 URL·상세이미지 해시가 모두 일치해야 합니다. 주니어 상품은 분석·적용에서 제외합니다.

공유 파일은 `research/official-benefits/manifest.json`과 `shard-0.json`~`shard-f.json`입니다. 공식몰 상품명·경로·본문·이미지 OCR·원문 근거·이미지 해시·진행 목록만 포함합니다. 컴퓨터별 절대 경로, 로그인 프로필, API 키, 비밀번호, 세션 토큰, 사용자 상품사진, MP4와 원본 이미지 파일은 포함하지 않습니다. 새 컴퓨터에서는 원본 저장 위치를 자동으로 다시 정하고 D드라이브가 있으면 조사자료에 우선 사용합니다.

등록기 실행 중 약 1분 간격으로 조사자료를 공유 파일에 반영하고 기존 GitHub 자동 반영 기능으로 main에 올립니다. 화면 상단의 분석 건수와 GitHub 반영 완료 상태를 함께 확인하세요. 프로그램 코드를 바꾸지 않은 분석 진행 갱신은 프로그램 버전을 올리지 않습니다. 컴퓨터를 끄면 분석은 멈추지만 다음 컴퓨터에서 최신 main을 받고 실행하면 마지막으로 GitHub에 반영된 체크포인트부터 이어갑니다. 이미지가 불명확하거나 원본이 없으면 확인 필요로 남기고 분석 완료로 꾸미지 않습니다.

GitHub로 진행 결과를 다시 공유하려면 그 컴퓨터에도 Git이 설치되어 있고 이 저장소에 쓸 수 있는 Git 로그인이 필요합니다. GitHub ZIP만 내려받아 Git 저장소 연결 없이 실행해도 자료 복원·로컬 분석은 가능하지만 진행 결과의 자동 업로드에는 Git 저장소 연결이 필요합니다. 두 컴퓨터가 동시에 main을 수정하면 기존 충돌 차단을 유지하며 강제로 덮어쓰지 않습니다.

환경변수 `REGISTER_BENEFIT_AUTORUN=0`으로 실행하면 공유 자료는 복원하되 자동 분석은 시작하지 않습니다. 같은 컴퓨터의 실행 중인 분석 작업은 재사용합니다.

## 홈페이지 신상품·변경 확인
등록기 실행 시 공식 성인 상품 목록과 원문·상세이미지를 확인하고 첫 결과를 기준선으로 보관합니다. 이후 30분 간격으로 재확인합니다. 원문·상품정보의 지문과 상세이미지 HTTP 검증자 및 실제 해시를 대조하며 변경 없는 OCR은 재사용합니다. 긴 분석은 체크포인트에서 다음 확인 주기로 넘겨 중복 작업을 피합니다. 상단 홈페이지 확인 요약을 펼치면 실제 변경 목록과 분석 상태를 볼 수 있습니다. 주니어는 제외합니다. 이 표시는 판매처 상품 저장이나 최종등록을 실행하지 않습니다. 컴퓨터가 꺼지면 확인도 중지되고 다음 실행 시 이어갑니다.

### 롯데 자동 로그인

롯데ON 탭의 **자동 로그인 설정**에서 한 번 계정을 저장하면 전용 크롬 연결 및 상품 입력 시작 시 공식 로그인 화면에서 한 번 자동으로 로그인합니다. 기존 로그인 세션과 입력 중인 다른 계정은 유지합니다. 로그인 실패·보안 인증·비밀번호 변경은 전용 크롬에서 직접 완료하며 반복 시도하지 않습니다. 설정에서 끄기·저장 정보 삭제가 가능합니다.

계정은 Windows 현재 사용자 DPAPI로 암호화한 `data/browser-login-settings.json`에만 보관하며 상태 API에는 마스킹된 계정과 사용 여부만 반환합니다. GitHub에는 코드만 공유합니다. 다른 컴퓨터나 Windows 사용자에서는 계정을 한 번 다시 설정하세요. 스마트스토어는 별도의 자동 로그인 설정과 계정을 사용합니다.

### 스마트스토어 자동 로그인

스마트스토어 탭의 **자동 로그인 설정**에서 평소 사용하는 **네이버 아이디** 또는 **이메일·판매자 아이디** 방식을 선택하고 계정을 한 번 저장하세요. 로그인 창 연결 및 상품 입력 전 확인 단계에서 해당 계정으로 한 번 시도합니다. 네이버 로그인은 커머스 화면에 연결된 공식 팝업만 사용하고 로그인 상태 유지를 켜며, IP 보안 설정은 그대로 유지합니다. 보안문자·2단계 인증·약관·계정 전환은 직접 완료하세요. 로그인 실패를 자동으로 반복하거나 상품 복사·저장·최종등록을 실행하지 않습니다. 원하는 복사등록/조회수정 화면은 직접 선택합니다.

롯데 계정과 분리된 `data/smartstore-browser-login-settings.json`에 Windows 현재 사용자 DPAPI로 암호화해 보관합니다. 로그인 방식과 마스킹된 계정만 상태 API에 반환하고, 네이버 API 연결 키와 별도로 관리합니다. 다른 PC에서는 계정을 한 번 다시 설정하세요.
